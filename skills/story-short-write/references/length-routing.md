# 短篇字数阈值

analyze / import / write 共用本表。用户显式声明长篇或短篇时，声明优先于字数。导入的章节结构分流由 story-import 单独维护，不在本表。

口径：`visible_chars_v1`（空白不计）。阈值是路由边界，不是质量分数。

| 区间 | 字数 | 拆文 `story-short-analyze` | 导入 `story-import` | 写作 `story-short-write` |
|------|------|---------------------------|---------------------|-------------------------|
| 默认短篇 | < 20000 | 直接进短篇管道 | 无章节结构 → 短篇 | 用户未指定范围时，须告知并获准 **8000–20000** 默认交付区间 |
| 灰区 | 20000 ≤ N < 30000 | 询问「字数 {N}，介于短/长之间，按短篇还是长篇拆？」；回「按短篇继续」才走短篇 | 无章节结构 → 仍判短篇，复述时告知已超过 20000 建议上界，请用户确认 | 用户明确范围优先；未指定时仍是 8000–20000，不因灰区改默认 |
| 偏长 | ≥ 30000 | 提示偏长、建议改走长篇拆文；仍要短篇须明确回复「按短篇继续」 | 无章节结构 → 不自动判定，请用户在长篇工程 / 短篇工程之间拍板 | 不是默认交付区间；只有用户点名更大范围才按用户范围写 |

写作侧补充：

- 用户给出上下限 → 逐字取其最小/最大值；只给单一目标 → 按目标上下各 5 个百分点。
- 投稿建议区间可以更短（常见约 8000–12000），不得覆盖用户锁定范围，也不得把投稿建议写成默认交付。

拆文侧补充：

- 导入流程已锁定篇幅后，analyze 的 Step 2 不得再问；按锁定结果答「按短篇继续」或改走长篇管道。
- 「按短篇继续」是用户或导入锁定给出的显式指令，不是默认。
